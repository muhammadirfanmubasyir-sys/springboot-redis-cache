# Spring Boot Redis Cache

A demo project showing how to use Redis as a cache with Spring Boot.

## Tech Stack

- Java 21
- Spring Boot 4.0.1
- Spring Data JPA
- Spring Data Redis
- H2 (in-memory database)
- Redis 7.4.2

## Running

Start Redis via Docker Compose:

```bash
docker-compose up -d
```

Run the application:

```bash
./mvnw spring-boot:run
```

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/product` | Create a product |
| GET | `/api/product/{id}` | Get a product by ID |
| PUT | `/api/product` | Update a product |
| DELETE | `/api/product/{id}` | Delete a product |

## Spring Cache Annotations

### `@Cacheable`

Caches the result of a method. On subsequent calls with the same key, the cached value is returned without executing the method.

```java
@Cacheable(value = PRODUCT_CACHE, key = "#productId")
public ProductDto getProduct(Long productId) {
    Product product = productRepository.findById(productId)
            .orElseThrow(() -> new IllegalArgumentException("Cannot find product with id " + productId));
    return new ProductDto(product.getId(), product.getName(),
            product.getPrice());
}
```

- `value = "products"` — the name of the Redis cache
- `key = "#productId"` — SpEL expression using the method parameter as the cache key
- First call: executes the method, caches the result
- Next calls with the same key: returns the cached value, method is **not** executed

### `@CachePut`

Updates the cache without skipping method execution. The method always runs and the result is stored in the cache.

```java
@CachePut(value = PRODUCT_CACHE, key = "#result.id()")
public ProductDto createProduct(ProductDto productDto) {
    ...
}
```

- `key = "#result.id()"` — uses the **return value's** `id` field as the cache key
- Why not `#productId`? The method parameter is `ProductDto`, not `productId`. Also, for `createProduct` the input `id` is `null` (auto-generated by the database), so using the result ensures the correct generated ID is used as the key
- The method always executes and the cache is updated with the new value

### `@CacheEvict`

Removes an entry from the cache.

```java
@CacheEvict(value = PRODUCT_CACHE, key = "#productId")
public void deleteProduct(Long productId) {
    productRepository.deleteById(productId);
}
```

- `key = "#productId"` — the cache entry with this key is removed
- The method executes normally and the cached entry is evicted

## Key SpEL Expressions

| Expression | Description |
|------------|-------------|
| `#productId` | References the `productId` method parameter |
| `#productDto.id()` | References the `id` field of the `productDto` parameter |
| `#result.id()` | References the `id` field of the method's return value |

## Cache Behavior Summary

| Operation | Annotation | Cache Action | Method Executes? |
|-----------|------------|--------------|------------------|
| Create | `@CachePut` | Adds entry to cache | Yes |
| Read | `@Cacheable` | Returns cached value if exists | Only on cache miss |
| Update | `@CachePut` | Updates cache entry | Yes |
| Delete | `@CacheEvict` | Removes entry from cache | Yes |

## Unit Tests

Tests are in `SpringBootRedisCacheApplicationTests.java`. Redis is flushed before each test using `FLUSHALL` to avoid stale data from previous runs.

### Running Tests

Run all tests:

```bash
./mvnw test
```

Run a single test:

```bash
./mvnw test -Dtest="com.irfan.mubasyir.demo.SpringBootRedisCacheApplicationTests#testCreateProductAndCacheIt"
```

### Test Cases

#### `testCreateProductAndCacheIt`

Verifies that creating a product via the API stores it in both the database and the Redis cache.

1. POST a new product
2. Assert the product exists in the database
3. Assert the product is present in the Redis cache

#### `testGetProductAndVerifyCache`

Verifies that the second GET request hits the cache instead of the database.

1. Save a product directly to the database (bypasses cache)
2. GET the product — cache miss, `findById` is called once
3. GET the product again — cache hit, `findById` is **not** called
4. Uses `@MockitoSpyBean` to verify the number of `findById` invocations

#### `testUpdateProductAndVerifyCache`

Verifies that updating a product also updates the cache.

1. Save a product directly to the database
2. PUT to update the product
3. Assert the response contains the updated values
4. Assert the cache contains the updated values

#### `testDeleteProductAndEvictCache`

Verifies that deleting a product removes it from both the database and the cache.

1. Save a product directly to the database
2. DELETE the product via the API
3. Assert the product no longer exists in the database
4. Assert the cache entry is evicted (returns `null`)

### Key Test Tools

| Tool | Purpose |
|------|---------|
| `MockMvc` | Simulates HTTP requests without starting a real server |
| `@MockitoSpyBean` | Wraps a bean to track method invocations while keeping real behavior |
| `RedisTemplate` | Used in `@BeforeEach` to flush all Redis keys before each test |
| `CacheManager` | Used to inspect cache contents directly |
| `@SpringBootTest` | Loads the full application context for integration testing |
